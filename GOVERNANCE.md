# Governance

## Overview

GRADE is an open-source project maintained by a small core team. This document describes how the project is governed, how decisions are made, and how new maintainers are added.

## Maintainers

Current maintainers are listed in [CODEOWNERS](./CODEOWNERS). The lead maintainer is **@jonathanbbechtel**.

Maintainers are responsible for:

- Reviewing and merging pull requests.
- Triaging issues and setting project direction.
- Cutting releases and managing the changelog.
- Enforcing the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Decision Making

For routine changes (bug fixes, small features, documentation updates), a single maintainer approval is sufficient to merge a PR.

For significant changes — new benchmark categories, changes to the public API, alterations to scoring methodology, or dependency additions — the lead maintainer will open an issue or discussion thread to gather community feedback before merging. A minimum comment period of 5 business days applies to such changes.

In the event of a disagreement among maintainers, the lead maintainer has final say.

## Becoming a Maintainer

Consistent contributors who demonstrate good judgement, familiarity with the codebase, and alignment with the project's goals may be invited to become maintainers. Nominations can be raised by any existing maintainer in a private discussion.

## Changes to This Document

Proposed changes to this governance document should be submitted as a pull request and must be approved by the lead maintainer.
